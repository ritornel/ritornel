# Desktop

The desktop app (`apps/desktop`, package `ritornel-desktop-gpui`, binary `ritornel-gpui`) is a GPUI client over `ritornel-client` and `ritornel-contract`. It never links `ritornel-engine` or `rusqlite` directly; every read, playback action, and cover fetch crosses the local server contract.

See [`docs/internals/contract.md`](contract.md) for the wire protocol and list views, [`docs/internals/platforms.md`](platforms.md) for per-OS support and bundling, and [`docs/internals/history.md`](history.md) for the server queries behind the History tab and Lean back.

## Workspace and server connection

- **Separate Cargo workspace:** `apps/desktop/Cargo.toml` declares its own `[workspace]` and is excluded from the root Cargo workspace so `ritornel-server`, `ritornelctl`, and headless hub builds never pull in GPUI or desktop libraries. It pins `gpui-pre` / `gpui-pre-platform` (`=0.3.13`) with `runtime-shaders` enabled by default so macOS builds only need Command Line Tools, and replaces `gpui-pre-linux` with Ritornel's patched copy, [ritornel/gpui](https://github.com/ritornel/gpui), for a touchpad's scroll on Wayland ("Linux" in `docs/internals/platforms.md`).
- **Discovery and launch (`link.rs`):** Resolves the data directory from `--data-dir`, `RITORNEL_DATA_DIR`, or the OS default. When a `ritornel-server` binary sits beside the app bundle, `Link` starts it if none is running (passing `--output` from `RITORNEL_TEST_OUTPUT` when set). Where `platform::SERVER_APART` is true (Linux and Windows), the server is launched detached so closing the window keeps music playing and Quit stops it; where false (macOS), closing the window keeps the app running in the Dock and Quit stops a server the app started. While disconnected, `Link` retries with backoff up to 2 seconds and reports the reason (`Why::{NotRunning, Starting, Unreachable, Incompatible, Lost, Failed}`). Until a session begins it also reads `preparing.json` four times a second (`Link::preparing`), since a server it launched says nothing else until it listens: while a server is copying, migrating or deriving history again, the title bar says "Updating your library…" and the Library and History pages say what is happening (`preparing_words`) instead of drawing an empty page. The title bar says "Connecting…" while looking, while a server is starting, and while looking again after a connection was lost, and "Not connected" only when there is no server to reach or none it can talk to (`link::unconnected`). Its mark is the working arc while it connects or the library is updated, and a red dot when it is not connected (see [Status](#status)).
- **A satellite's hub (`away.rs`, `frame.rs`, `player.rs`, `wall.rs`, `album.rs`, `artist.rs`):** On a satellite, the title bar names the hub beside a green dot. Once the hub has not answered for `QUIET_MS` (5 seconds), so that a hub back at once needs no word, the dot becomes an amber ring and a toast says so once, and another says when it is back. Hovering the name shows what is wrong, since when, and what still works. A wall already drawn stays; one that could not be read says why in its place and is read again when the hub answers. While the hub is away the wall asks nothing of it. When it is back the wall resumes once: its view, which ended with the hub's connection, is replaced keeping the row at the top in place, and album and artist pages read themselves again. An artist page keeps which of its pictures (face, portrait, blurs) failed this time, not those the server has none of or cannot make, and asks for each of them again once when the hub is back or a new session begins, a read still under way then included; it lets the set go when it shows another picture. An album page asks again at once for a picture whose read failed, then after its usual waits. Neither asks again for a picture it has read. The app learns of the hub from the satellite's `servers` events (`Net::hub`).
- **Network runtime (`net.rs`):** Runs `ritornel-client` and a kept-alive HTTP/1.1 cover fetcher (`ArtHttp` using `hyper`, reading `GET /v1/art/{artId}/{size}?token=`) on a dedicated 2-worker Tokio runtime (`"net"`, falling back to a single-thread runtime if needed). GPUI's foreground executor awaits Tokio handles directly.

## Frame and navigation

- **Window chrome (`frame.rs`, `shell.rs`):** The title bar holds five tabs (`Tab::{Today, Library, Playlists, History, Devices}`), the lit one in the accent on its tint as a lit button of the player bar is (`theme::lit_words` on `theme::lit`), a global search box (`search.rs` calling `library.search` as you type), and either system window buttons or drawn controls per `platform::CHROME`. Menus live in the OS menu bar where `platform::CHROME.menu_bar` is true (macOS) and open from a title-bar button via `drawn.rs` elsewhere, driven from one menu definition.
- **Keyboard focus (`shell.rs`, `search.rs`):** The shell's focus handle holds keyboard focus whenever no text field needs it, and its key handlers are the window's shortcuts: Space, the skip keys, Esc, Back, and the wall's type-to-find. `⌘F` (Ctrl+F off a Mac) focuses the search field. Every way out of Search (choosing a result, Esc, or clicking outside the field and its results) clears the field and, if the field still has focus, focuses the shell's handle. Clicking outside closes Search in the capture phase, before the click reaches its target, so a control that takes focus on click still takes it.
- **Player bar (`bar.rs`):** Shows the current track's cover, title/artist, star rating, transport controls, draggable seek bar, the place-and-volume widget (`speaker.rs`, see [Play on](#play-on)), Up next toggle, and Lean back trigger. The right-hand group is the widget, a 6 pt gap, Up next and Lean back: 240 pt at its narrowest. While the player waits for its audio (`Buffering`, as a satellite does while it pulls a track from its hub), the transport treats it as playing, so Pause shows, and pressing it pauses the wait for sound. For the first `BUFFER_QUIET` (500 ms) the cue shows nothing, so a song already at hand never flickers. Then the seek bar's empty part breathes, one breath every 1.6 seconds starting from rest (`player::breath`). After `BUFFER_SAY` (5 seconds), the line under the title says `Getting it from <hub>…`, in place of an output notice, since the output is not tried again until the audio is here. The clock and the moving bars hold still, since they advance only while it plays. All of it ends with the first state that is not `Buffering`, or sooner with a `progress` event that says the entry plays, since the two topics are sent separately; a new session ends it too. The wait keeps its start across songs (`waiting_since`), and the cue draws frames only while it breathes.
- **Whole-page history stack (`stage.rs`):** Navigating deeper pushes the previous `Page` entity onto `History<P>` (up to `DEPTH = 100` entries) rather than tearing it down, so Back restores exact scroll position and state immediately. Off-screen pages track missed server updates via `Freshness` and refresh once when shown again instead of re-reading on every play event. Pages pushed deeper than the nearest two back-stack entries release their cached pictures (`trim_behind`) and reload them if revisited so deep navigation chains do not pin GPU memory.
- **Transitions (`shell.rs`, `moves.rs`):** Page changes stage the outgoing page beneath the incoming one and animate shared artwork (`Carry`) between wall tiles, album covers, artist portraits, and the player bar.
- **Hover and press (`theme.rs`):** Every control answers the pointer with shared styles rather than colours of its own, passed as `.hover(theme::hovered)` and `.active(theme::pressed)` or combined in a closure. Under the pointer, a control with no ground at rest takes `fill` (`hovered`), one resting on `fill` or inside a hovered row takes `fill2` (`hovered_on_fill`), words or an icon alone turn to the ink (`hovered_ink`), and a control solid with the ink drops to `0.88` opacity (`hovered_solid`). Pressed, every enabled control drops to `PRESSED` (`0.8`) opacity, which keeps even `faint` words at 3:1 on the palette's grounds. A Settings row whose whole length is the target (a switch's, a time zone's) takes `fill` while pressed instead, since the click lands on an unseen layer over it. Cover tiles and record cards rise 2 points under the pointer (`lifted`) and settle while pressed (`settled`). Rows that act on a double-click or a drag (songs, Up next entries) take only the hover, so a double-click does not flash, and targets that act on the press itself (stars, a song's play button, Search's results and drawn menus) answer with what they do. Disabled controls take neither. Controls over a picture keep grounds of their own: Lean back's take the ink at 12%, and the banner's pills lighten as solid controls do. Windows' close button turns red, as the system's does. The Settings window's push buttons and pop-ups, drawn like AppKit's, take only the press, as AppKit's do.
- **Appearance and local state (`theme.rs`, `accent.rs`, `remember.rs`):** Follows OS light/dark appearance automatically (`Mist` light, `Graphite` dark; overridden for testing by `RITORNEL_GPUI_APPEARANCE=light|dark`), as GPUI reports it on every system. The accent follows the system's too: `platform::accents` sends its first reading and each change, from any thread, to a task in `main.rs` that hands it to `theme::follow_accent` and redraws every window. `accent::derive` keeps the system accent's hue and as much of its Oklab chroma as the appearance's look allows (`theme::DARK_LOOK` `0.12`, `theme::LIGHT_LOOK` `0.18`), starts from the palette's lightness (`0.76` dark, `0.55` light), and moves that lightness away from the grounds until the accent, rounded to the bytes the renderer draws, reaches WCAG 2 contrast of `4.5` on `bg`, `bar_bg`, `surf` and `raised`, and on its own `LIT_TINT` (14%) over each, where a lit player bar button and the lit tab draw it. In the dark, `0.12` is about the most chroma every hue can show in sRGB at that lightness, so each vivid accent keeps the same chroma and none needs lightening to be read. An accent with less chroma than the look allows keeps its own, and a grey one stays grey. Both appearances' accents are worked out once per change, so `theme::acc()` stays a load. Where the system names no accent (a Mac on Multicolor, Linux without a portal accent, or any other system), `acc()` is the palette's own (`#8fb4d9` dark, `#5a61d6` light). The Settings window's switch and progress bar, drawn to look like the system's controls, wear the system's accent as it is, darkened only where their white knob would fall under 3:1 on it (`accent::control`, `theme::system_accent`), and where it names none, the system's own default (`platform::CONTROL_ACCENT`): AppKit's blue (`#027aff`) on a Mac on Multicolor, Windows' default blue (`#0078d4`), and on Linux, where the portal reports no accent, the app's fallback of `#3584e4`, GNOME's default blue. `RITORNEL_GPUI_ACCENT=#rrggbb|none` holds an accent for testing. The accent marks what is lit: set stars, the seek bar and a volume slider under the pointer or held, a lit button of the player bar, the title bar's lit tab, the mark of the song playing in a song list, Up next and the picker, the chevron of the wall's sort pop-up, Search's focus ring, and the ring round a marked tile. What is lit on a ground of its own wears the accent on `theme::lit()`, the accent at `LIT_TINT`. Machine-local UI preferences (`wall`, `albumsSort`, `letters`, `settingsSection`, `playOn`, `volumeControl`) persist in `dev.ritornel.desktop-gpui/remembered.json` under `platform::settings_dir()`, and `Looks` is shared globally across windows.

## Status and buttons

### Status

A status's colour says whether it is fine, being done, waiting on you, or wrong (`theme::Status`), its shape says whether the thing is here (`marks::Mark`), and its words always say it too, so it reads without the colour. No status colour follows the accent.

| `Status` | Means | Mark (dark / light) | Text (dark / light) | Tint (dark / light) |
|---|---|---|---|---|
| `Quiet` | Nothing to do | `faint` | `dim` | — |
| `Ok` | Here, nothing to do | `#3aae86` / `#1f8f64` (`ok`) | `#3aae86` / `#17704e` (`ok_text`) | — |
| `Working` | Being done now | `#8fb4d9` / `#5a61d6` (`working`) | `working` | — |
| `Need` | Waiting on you, nothing lost yet | `#e0ad48` / `#c2820a` (`need`) | `#e0ad48` / `#8f6207` (`need_text`) | `rgba(217,164,65,.13)` / `rgba(194,130,10,.12)` (`need_tint`) |
| `Fail` | Failed, or losing something | `#ee6a5f` / `#d23f32` (`fail`) | `#f47c72` / `#b52b20` (`fail_text`) | `rgba(238,106,95,.12)` / `rgba(210,63,50,.09)` (`fail_tint`) |

- **Marks and text (`theme.rs`):** A mark holds 3:1 on `bg` and `raised`, and text holds 4.5:1 on all four grounds and on `fill` over `bg`; the tests in `theme.rs` check both. Amber and red marks also differ in lightness by at least 1.4:1, since a badge has no words beside it. `working` is the palette's own accent, held apart from `acc()`, so a system accent of red or green never reads as a status.
- **Shapes (`marks::Mark`):** `Working` is an open arc, three quarters of a ring, that the renderer turns once a second at up to 30 frames per second (`TimedTransformation::rotation`), so nothing is laid out again while it turns. It holds still while `platform::reduce_motion` says so: on macOS that follows the system's Reduce motion setting, and on every system `RITORNEL_GPUI_REDUCE_MOTION` asks for it, for checking; Linux and Windows do not read their own setting yet. The Settings window draws the same arc, 12 points, for every wait with no end to show (signing in, reading time zones, importing pictures or the history), while its scan keeps the progress bar in the system's accent. Any other status is a filled dot while the thing is here, and a ring, 1.5 points wide, while it is not.
- **Title bar (`frame.rs`, `link.rs`):** The connection's mark, 8 points, is a green dot while connected, an amber ring while a satellite's hub does not answer, the working arc while connecting (the first look and each asked for with Look again, but not the quiet retries between, so a failure stays said), while a server starts or is looked for again after a lost connection, and while the server updates the library or saves a copy of it first, and a red dot while there is no server, none that answers, one from another release, or one that could not be found.
- **Where each colour is used:** Amber says a folder is offline (with a ring beside it), a sign-in is needed again (on Last.fm's Account row and in the listening record), listens wait to reach history, and a place played on is out of reach. Red says an output failed, scrobbles are refused, a listen cannot be saved, an import or a scan failed (a folder's rescan or import on its own included), and what the library, an album, an artist, the history, the search, Last.fm's settings, or the listening time zones could not be read. The record's notes (scrobbles unanswered or withdrawn) are quiet. Settings' `problem` lines, what went wrong under a box, are red. A place's trouble (`places::Trouble::status`, `places::Trouble::mark`) is amber for one out of reach, with a ring in the picker, and red for one whose output failed, with a dot, alike in the player bar's notice, the Play on widget, its hover card and the picker's row. In the picker, a place out of reach fades its icon and name but not its ring or line, and is never lit, since neither the pointer nor the keys can choose it; a place whose output failed is lit with `theme::fail_hover` rather than `fill`, on which its red line would fall to 4.1:1 in the dark.

### Buttons

`button::button` draws a capsule 36 points tall, with its label at 14 points and weight 600, for each `button::Role`:

| `Role` | Looks | For |
|---|---|---|
| `Play` | `ink` ground, `bg` words | Starting music on a record, an artist or a playlist, and nothing else |
| `Primary` | `acc()` ground, `theme::on_accent` words (`bg` in the dark, white in the light) | What the page is for, at most one in view |
| `Secondary` | `fill` ground, `ink` words | Everything else, such as a blank page's button |
| `Quiet` | `acc()` words, no ground | Opening more of the same thing, at a row's end or in a sentence |
| `Destructive` | No ground, `fail_text` words, a `fail` edge | Taking something away |

Under the pointer, `Play` lightens as a solid control does, `Secondary` takes `fill2`, and `Quiet` takes `fill`. `Primary` moves its accent 12% toward the ink (`theme::primary_hover`) and `Destructive` takes `fail` at 8% (`theme::fail_hover`), so their words stay at 4.5:1 under the pointer on every ground, which the tests in `theme.rs` check against the app's accent and several system ones. `Destructive` has no neutral ground because its red words fall to 4.1:1 on `fill` over `raised` in the dark. A blank page's button is `Secondary`; the Devices tab uses `Primary`, `Secondary`, `Quiet` and `Destructive`. The banner's Play and Shuffle pills keep grounds of their own over its picture, and the Settings window's push buttons are drawn as AppKit's.

## Walls, pages, and history views

### Library walls and cover loading

- **Virtualized walls (`wall.rs`, `layout.rs`):** `Wall` switches between `WallKind::Artists` and `WallKind::Albums` (sorted by `artist`, `title`, `year`, or `added`), drawing only visible rows on a `150` pt tile grid (`MIN_COLUMNS = 3`, `MAX_COLUMNS = 16`, `GAP_X = 18`, `GAP_Y = 22`) in one of three section shapes (`Shape::{Lettered, Headed, Dated}`). Rows stream in pages of `100` (`PAGE = 100`, up to `KEEP_PAGES = 200` cached, `PAGES_IN_FLIGHT = 4`) through a server `list.open` view kept alive every `KEEP_VIEW` (4 minutes). A page whose read fails for any reason but an expired view is marked `Page::Failed`, and no page is read until a wait ends: `RETRY_FIRST` (1 second), doubled with each failure in a row up to `RETRY_MOST` (30 seconds). A failed replacement of the view waits the same way.
- **Ordering and type-to-find (`wall.rs`, `find.rs`, `crates/ritornel-engine/src/list/fold.rs`):** Both server-side list ordering/search and client-side type-to-find (`TYPING = 1000` ms timeout in `wall.rs`, query folding in `find.rs`) fold case, accents, and word-separating punctuation so typing jumps directly to matching titles or artists.
- **Momentum-predicted cover loader (`covers.rs`, `wall.rs`):** Each frame the wall reports `Wants { ids, px }` ordered by predicted scroll rest point first, then visible tiles, then look-ahead in the direction of travel, bounded to the cache's working set so look-ahead covers do not evict and re-decode each other. Up to `MAX_FETCHES = 8` concurrent HTTP fetches run at once; stale requests, for covers no longer wanted or wanted at other pixels, are aborted (letting the server drop unstarted jobs from `CoverPool`). A cover sent is not asked for again while the wall's list still names it at the same size, as it does until the wall takes it in; one read but no longer wanted by the time a decoder is free is kept compressed and asked for again as soon as it is wanted. Decoding and blurring share a global semaphore (`decoders()` clamped to `2..=4` blocking threads). Memory is bounded by `COMPRESSED_BUDGET` (`32 MiB` in `covers.rs`) and a decoded pixel budget defaulting to `96 MiB` (`cover_budget()` in `wall.rs`, overridden by `RITORNEL_GPUI_COVER_MB`), evicting least-recently-drawn images through `drop_unshared` from both RAM and GPUI's sprite atlas while keeping each cover's average color (`ground`) so tiles never flash blank. Per-page image tasks register in `FetchBag` or `AbortOnDrop` and abort on drop or replacement.

### Album and artist pages

- **Discography shelves (`artist.rs`, `album.rs`, `crates/ritornel-engine/src/list/discography.rs`):** An artist's records are ordered server-side (`SortKey::Discography`) into shelves—albums and EPs (including untyped releases), singles, live recordings, collections and rarities, and appearances—newest first by original release year, with undated records last.
- **History on pages (`history.artist`, `history.album`):** Artist and album pages display a banner summary sentence (`Phrase`), yearly play counts (`YearPlays`), and (for artists) top played records, re-reading when plays change. The yearly play counts need dated plays (`pictured`); an artist's top played records (`RecordPlayed`) show without them, since undated plays rank them too.

### History tab and Lean back

- **History tab (`history.rs`, `stream.rs`, `thisday.rs`):** Calls `history.stream` and `history.onThisDay` to render a full-bleed, smoothed monthly listening stream layered by the year each artist was first heard (square-root height scale so quieter years remain legible, with catch-up sync days above `SYNC_DAY = 300` plays excluded server-side in `history_stream.rs`), with hover/click inspection and an "On this day" column (up to `AT_MOST = 3` years, applying the same `SYNC_DAY = 300` exclusion in `thisday.rs`).
- **Lean back (`lean.rs`):** Full-window Now Playing overlay (`⇧⌘F` / player bar button) over blurred album artwork. Cycles `history.track` facts every `FACT_MS` (14 seconds) or via `←`/`→`, using letter-spacing tracking (`tracked.rs`) and a Rust port of WebKit's `InlineContentBalancer` for balanced multi-line headings.

## Devices

The Devices tab (`devices.rs`, `devices/art.rs`) is what the library is synced to. It holds nothing of its own: everything shown is read with the `devices.*` calls and read again when a `devices` event names the device ([Devices](contract.md#devices) in the contract guide, and the [devices guide](device-sync.md) for what is behind it).

- **The column of device tabs:** Down the left, `COLUMN` (216 pt) wide and level with the page's top: each device's small drawing, its name and its state with its mark, the one shown on a `raised` card with a hairline. It does not scroll with the page. A long name wraps to a second line. With fewer than two devices it is not drawn and the page has the window's width. Its `+` opens a menu with `Add Folder…`, which asks for a folder with the system's picker (`platform::choose_folder`); with one device that item is in the page's `···` menu instead. Drives are never offered unasked.
- **Drawings (`devices/art.rs`):** A device is drawn as the thing itself, in its own colours: a folder, a drive, a car stereo, a phone, a player, an iPod Video in white or black, a Zune 30 in brown. Each is an SVG made in code and drawn as a picture, since GPUI's `svg` element draws one colour. A drawing is known by a key the server names, such as `folder.car_stereo`; a key with no drawing falls back along its path. `art` fits a drawing in a box, 34 by 26 points in a tab and 96 by 62 on a page, so a wide stereo and a tall player both sit right.
- **A device's page:** The same before and after setup. Its top has the drawing, the name, its state and a line of facts; three figures for the next sync, to copy, free after and how long; one `Primary` button, `Set up and sync` for a device not yet set up and `Sync` after, none while a sync runs, when `Stop` (`Secondary`) takes its place; `Eject` where the device is ejected; and `···` with Rename, Ignore and Forget. Forget asks first, in a tinted box with a `Destructive` button. Under the top are the views in the app's segmented control, as the Library's Artists and Albums are, and one bar of room: what Ritornel has on it, what the sync would add, what is left alone, and where the reserve begins.
- **Views:** Sync and Music, and Plays for a device that gives plays back; a folder has no Plays. A device opens on Music until it is set up and on Sync after, unless a view was chosen by hand. **Sync** is what happens next: a tinted box when not everything fits, with `Sync what fits`; counts that filter the rows (All, Add, Replace, Remove, Conflicts, Blocked); and the rows by album, each opening to its tracks. While a sync runs it shows the steps, done, running and to come, a bar, the file in hand, and the run's own rows changing in place. **Music** is what goes on and in what form: the sources in order, each with its albums and size and what of it does not fit; Leave out and Always as chips; a search for an artist or an album to add (`library.search`); the files already on it that are not Ritornel's, behind Review; and menus for what a folder is made for, the format with what the content takes in each, covers, whether it is removable, and a limit for one that is always here.
- **State (`state_of`):** One mark and a few words for each device, as [Status](#status) has them: the working arc while it syncs; quiet grey for one not set up, ignored or away, a ring where it is away; amber where it waits on the person (not everything fits, files changed on it, a sync cut off); red where files failed; green otherwise, with what is waiting to sync.

## Queue, context menus, and Settings

- **Now-playing bars (`marks::Equalizer`):** In track lists, Up Next and the place picker, each of the three bars reveals a narrow slice of a moving SVG mask. Its edge traces the 900 ms rise and fall, with 300 ms between bars. When the bars alone need frames, GPUI translates the sprites in the retained scene at up to 30 presentations per second, whether the visible window has focus or not. During playback the player’s 250 ms ticker drives about four shell, list and card renders per second. Input and server updates can trigger others. A fully clipped or removed mark contributes no animated sprites to the next scene. Pausing holds the playback phase, and Reduce Motion shows a fixed mark.
- **Up next and drag-and-drop (`upnext.rs`, `carry.rs`, `player.rs`):** Up next is a `320` pt floating card showing the current entry plus up to `UP_NEXT = 150` upcoming entries. At window widths `>= ROOM_FOR_CARD` (`1180` pt) it shifts the page over (`RAIL = 328` pt); below that it overlays the page and closes on navigation. `carry.rs` implements in-window drag-and-drop for songs, albums, and queue rows into `QueuePlace::{Next, After, End}`. `Player` tracks `playback` and `progress` events, applies optimistic star ratings (rolling back on error), and surfaces transient errors for `TOAST_MS` (`2600` ms).
- **Context menus (`menu.rs`):** Uses native OS pop-up menus (`platform::pop_up_menu`, `NSMenu` on macOS) or drawn menus (`drawn.rs`) for tiles, tracks, queue entries, artists, and the playing track, visually marking the target item while open.
- **Settings window (`settings/`):** Single secondary window (`WIDTH = 640` pt, height fitted to content within `SHOW_WITHIN = 1000` ms before display, non-resizable and non-minimizable) sharing the main `Link`, with four sections: `Library`, `Appearance` (the large letters, and the player bar's volume slider), `Last.fm`, and `About`. On Windows (`platform::CHROME.app_buttons`), its header answers the system's hit test as the caption (`WindowControlArea::Drag`) and draws a top-right close button via `frame::close_button`.

## Play on

The desktop plays on this computer's server or on another place the library can play on, chosen from a picker in the player bar. It is shown only when the server's descriptor lists the `players` capability; see [Player presence](contract.md#player-presence), [Routing playback and queue calls](contract.md#routing-playback-and-queue-calls) and [Moving playback](contract.md#moving-playback) for the wire.

- **Places (`places.rs`):** `Places` reads `players.list` on each session, on every `players` event and on each restated status, keeping only the latest read. The place played on is `Player`'s `target`: `None` for this server's own player, or a `playerId` from the list. A server that becomes a hub or a satellite during a session gains the `players` topic and the picker without reconnecting.
- **Routing (`player.rs`):** With a target, every `playback.*` and `queue.*` call carries it as `player`, `events.subscribe` with that `player` follows its `playback`, `progress` and `queue` topics beside the session's own, and events whose `player` is not the target are ignored. One task per session (`follow_places`) changes what the session follows, one change at a time and in order: it unsubscribes the old place before subscribing the new one, asks again every 2 seconds until a subscription works, and unsubscribes the last place when the player or the session ends. Taking a place over with nothing moved clears the shown state and Up next; after a move they stay until the new place reports (below). Either way the app reads `playback.get` and `queue.window` for the new place. A generation counter, raised on each change of place and session, drops reads and command failures that answer for one already left. Lean back's next-song read follows the target too.
- **Choosing a place:** With an entry at the place played on and that place reachable, choosing another calls `playback.move` with `from`, `to` and the current `entryId`, under one idempotency key, and changes target only once the move is answered (`Player::moved_to`). While the move is under way, a report from the place it leaves that it is empty is held back, and shown only if the move fails. Once it is answered, the song shown stays, marked stale with the clock held and progress ignored, its output trouble not taken for the new place's, until the new place's first state replaces it whatever its revision; while that place's reports name the moved entry without its track, the song's name, cover and length stay. So the bar never blinks to Nothing playing between two places. A read of the new place that fails is asked again every 2 seconds until one lands, since a paused place sends nothing by itself. The slider keeps its place and the last level, so the widget keeps its shape, and it and the volume keys answer again with the new place's first state; choosing another place waits for it too. A place taken over with nothing moved shows the last level the same way until it is read. Until then the widget stays as it was and its slider stops answering. A move whose answer is lost with its session is sent again once, under the same key, on the next session, since the hub answers a resend with what it did. With nothing to move, or from a place out of reach, the target changes at once and nothing moves. Before the source's state has been read, nothing is chosen. A failed move says so in a toast and leaves the target as it was. A place out of reach cannot be chosen.
- **Restart:** The remote target is remembered as `playOn` in `remembered.json`. On the first list read after launch the app returns to it only if it is listed, reachable, and `playing` or `buffering`; otherwise it starts on this computer and forgets it. A place that leaves the list sends the app back to this computer. While a satellite's hub is away the satellite lists only itself, so that list neither decides the restart nor drops the place played on, which stays listed as out of reach since the hub went.
- **The widget (`speaker.rs`):** `WIDTH` (164 pt) in every state, with the speaker icon at its right end; only that icon opens the picker. `places::look` decides what it shows: nothing, the icon (when other places exist), a slider led by a volume icon under `always`, or, for another place, an accent tint (`theme::LIT_TINT`, 14%, which the accent's contrast is worked out against) with the place's name (12 pt, weight 500, faded at its end by a gradient rather than an ellipsis) above a 12 pt volume icon and that place's slider. The volume icon shows the level (`volume0` to `volume2` by `waves`) and a click on it mutes or unmutes with `playback.set`'s `muted` alone, leaving the volume as it is, after sending any level a scroll still holds; moving the slider unmutes. The slider has a round thumb (`THUMB`, 6 pt) that grows to 8 pt under the pointer and while held, and its line is inset by the thumb's half so the thumb stays within what takes the pointer. Under `never` it shows the name alone. A place out of reach takes the amber of `Status::Need`, and one whose output reports a problem the red of `Status::Fail` (`places::Trouble::status`); either way its slider dims and stops answering, and the hover card's sentence is in that colour's text form. Hovering the name, and only the name, shows the whole name when it does not fit and the whole trouble sentence, never while the slider is held or the picker is open. The preference `volumeControl` is `remote` (default), `always` or `never`, chosen in Settings › Appearance under Player bar (Other places only, Always, Never). It is part of `remember::Looks`, so a choice there is remembered and shows in the bar at once. The speaker icon, the volume icon and the picker's rows take the shared hover and press styles (`theme::hovered`, `theme::hovered_ink`, `theme::pressed`). While the picker is open the speaker icon is lit as Up next's button is while its card is.
- **Volume input:** A slider drag, which a press up to `GRAB` (4 pt) above or below the line also starts (never past its ends, so a press on the icons beside it is theirs), sends `playback.set` with `volume` at most every `SEND_EVERY` (100 ms), and once more on release (`Throttle`). While held it shows its own level. Sends wait for the one before, so the place hears them in order, and a drag or scroll belongs to the place and session it began on: a change of either, or a slider that stops answering, ends it unsent. After a send, `Player` keeps the sound it set over reports of another while any set is unanswered and for `VOLUME_SETTLES` (1.5 s) after the last is answered, so a late report of an earlier send does not move it back; if no report confirms it in that time, or the send fails, the sound is read again (`read_sound`): a state of the revision shown gives its volume and muting alone, and a newer one is taken whole. A scroll on the widget moves the volume only when its gesture begins with the pointer at rest there for `REST` (250 ms), and never during momentum (`ScrollGate`, using `platform::scroll_details` where the system reports momentum). `⌥↑` and `⌥↓` (`platform::KEYS.skip` with ↑ and ↓) move it by 5% while an answering slider is shown.
- **The picker:** A card above the widget listing this computer first (`platform::THIS_COMPUTER`), then reachable places by name, then dimmed places that cannot be reached (`order`). Each row's second line says `Playing · <title>`, `Paused · <title>`, `Idle`, `Speakers not working since …` or `Away since …`; the chosen row has a check and a playing row has the moving bars. The order is fixed when it opens: later lists update rows in place, drop places that left, and append new ones (`Picker::refresh`). Its height is capped to the window, the list scrolling to keep the row the keys are on in sight. The shell routes ↑, ↓, Return and Esc to it while it is open, so keyboard focus stays on the shell's handle. It occludes what is under it, so nothing behind it answers the pointer. A click outside it, Search and Lean back close it.
- **Notices:** While the place played on is out of reach the bar's two lines say `Out of reach since …` / `It plays on by itself`, in place of any wait for its audio, the transport dims and the clock holds, and its state is read again once it is back; with an output problem they say `Speakers not working since …` / `Check they're on, then press Play`. A toast says the place is out of reach after `away::QUIET_MS` (5 seconds), once, and again when it is back. Errors from a routed call use short words (`Out of reach right now`, `Busy. Try again in a moment`).
- **Motion (`Light`):** Lighting up takes 240 ms on the toast's curve, the tint growing leftwards from the icon's button, with the name following 60 ms later and rising 3 pt. Going out takes 160 ms, the name first. Moving between two remote places changes only the name. The trouble's colour fades in over 300 ms, and the last trouble's colour is kept while it fades out. With Reduce motion only the fades run. Frames are requested only while something changes.

## Platform layer and testing

- **OS isolation (`platform/`):** All OS-specific code (`mac.rs`, `mac_menu.rs`, `mac_window.rs`, `linux.rs`, `windows.rs`) sits behind `platform/mod.rs` exposing `CHROME`, `FEEL`, `KEYS`, native file choosers, menus, server lifecycle, memory footprint reporting, and window screenshots. Overscroll elasticity on macOS (`elastic.rs`) ports WebKit/AppKit physics directly. No OS `cfg` appears outside `platform/`.
- **Unit tests on GPUI's test platform:** The desktop crate takes `gpui-pre`'s `test-support` feature as a dev-dependency, so tests can open windows on GPUI's headless test platform and drive focus, keys and clicks (`#[gpui::test]`), as `search.rs`'s focus tests do. `link::unlinked` gives such tests a `Link` that never looks for a server.
- **Scripted verification and benchmarks (`script.rs`, `measure.rs`, `waits.rs`, `scripts/desktop.sh`, `scripts/desktop.ps1`, `scripts/desktop-memory.py`):** `ritornel-gpui` accepts `--script "<steps>"` (driving waits, screenshots, scrolling, navigation, menus, drag/drop, Settings, and memory logging; `count` prints the shell renders and cover read attempts since the last count, and `held` whether a finished drag still holds a picture and how many pictures wait to leave the sprite atlas) and `--measure <seconds> --out <path>` for scroll benchmarks. With `RITORNEL_GPUI_WAITS=1`, the wall and artist pages time each tile, on the page on screen once it can be seen, from the frame it is first shown to the first that draws its picture at the size it is shown at, and the script's `waits <label>` step prints those times; `scripts/desktop-memory.py --waits` reports their median and slowest while flinging each wall, opening an artist's page and going Back, and `--slow` keeps the app on the efficiency cores. `scripts/desktop.sh` and `scripts/desktop.ps1` provide `check` (formatting, clippy, tests, and the `gpui-pre-linux` patch check), `release` (release build), `app` (bundled app with its server), and `run`/`tones` (launching against invented libraries in `apps/desktop/.invented` and `apps/desktop/.tones` by default, never a user's real data directory; `scripts/desktop.ps1 run` also accepts `-DataDir`).
- **Offscreen runs (`scripts/hidden-display.sh`):** Setting `RITORNEL_OFFSCREEN=1` on macOS resolves a hidden display via `RITORNEL_TEST_DISPLAY` or `hidden-display ensure` (left running for reuse), opens the window on that display out of the Dock (`keep_out_of_the_dock`), and refuses to start if no hidden display is available.

## Decisions

- **GPUI in an isolated Cargo workspace.** Keeping `apps/desktop` out of the main workspace prevents desktop/GUI dependencies from touching server and headless hub builds while letting the app compile directly against `ritornel-client` and `ritornel-contract`.
- **Whole-page history stack with deferred `Freshness`.** Retaining visited page entities gives instant Back navigation without losing scroll position, while coalescing background library updates avoids wasting work on off-screen pages.
- **Momentum-predicted, bounded cover loading.** Prioritizing predicted scroll rest points, aborting stale fetches, bounding both compressed and decoded caches, and caching average tile colors keep fast scrolling smooth and memory bounded without blank tiles.
- **Search hands focus back, never drops it.** Closing Search focuses the shell's handle rather than blurring the window, because with nothing focused no key handler runs and every shortcut stops working. Clicking outside closes Search even when nothing was typed, since a control that stops the click's propagation leaves the shell no chance to take focus itself.
- **Failed reads wait, and the hub's absence stops them.** A page that failed is not removed, so the next frame does not ask for it again: a server answering every read with an error is asked a few times a minute rather than once a frame. A hub known to be away is not asked at all, and its return resumes each view once rather than leaving it to the next failure.
- **The accent is derived, not used as given.** A system accent can be any colour, and the app's accent is read as text and thin lines on its own grounds. Keeping its hue, at the palette's lightness and one chroma for every hue, and moving it until it meets 4.5:1, keeps a bright yellow or a pale pink readable and no accent louder than another, while the app plainly wears the system's colour. The derivation is a pure function of the accent and the appearance, so a choice made in the app's settings later can take the system's place in `theme::follow_accent`.
- **Status colours are fixed, and working has its own.** A status must mean the same whatever accent the system names, so `ok`, `need`, `fail` and `working` never follow it; a red or green accent can only colour what is lit or chosen, and shape (the arc, the ring) tells working from a status where colour cannot.
- **Marks and text have separate colours.** A mark needs 3:1 and must stay apart for someone who cannot tell red from green, while text needs 4.5:1 on the page and on a button's fill, so the light theme's text forms are darker than its marks.
- **The lit tab keeps the ink over a banner and with a grey accent.** The accent's contrast holds on the palette's grounds, not on a cover's colours, so the lit tab keeps the ink on `fill` while the title bar lies over an album's or an artist's banner, as other controls over a picture keep grounds of their own. A grey accent, a Mac's Graphite or GNOME's slate, has no hue to tell a lit tab from the `dim` ones beside it (`accent::has_hue`), so its words keep the ink. The seek bar's played part stays in the ink at rest, so that turning to the accent still answers the pointer.
- **The music moves, the choice is not kept.** Choosing a place moves what is playing there in one server call, because the desktop cannot move a listen, position and shuffle order with the existing calls and a resend of one idempotent call is safe where several are not. A remote choice is forgotten at launch unless that place still plays, so Play pressed later never starts music somewhere unexpected.
- **The picker's keys go through the shell.** The shell's focus handle keeps keyboard focus while the picker is open, and the shell asks `Places::key` first, so closing the picker never leaves the window without a focused handler.
- **Contract-only client.** Keeping all library, discography ordering, history, and playback logic in `ritornel-server` ensures desktop and CLI share one source of truth and playback survives window closes.
