# Linking

Every `ritornel-server` creates a durable cryptographic identity on first start, enforces a single-writer hub boundary on `library.db`, and authenticates clients with owner-only session credentials, single-use socket tickets, and session-scoped media tokens. Identity and session storage live in `crates/ritornel-engine/src/{server_store,library_store,secret}.rs`; credential management, library opening, listener limits, tickets, and media tokens live in `apps/server/src/{credential,library,config,listener,ticket,media,dispatch}.rs`; contract types live in `crates/ritornel-contract/src/{server,ticket}.rs`.

See [`docs/internals/server.md`](server.md) for the data directory and storage split, [`docs/internals/contract.md`](contract.md) for HTTP routes and origin checks, and [`docs/internals/schema.md`](schema.md) for the `server.db` and `library.db` table definitions.

## Server identity and hub role

- **Durable identity (`server_store.rs`, `secret.rs`):** On first start, `ServerStore::ensure_identity` creates the singleton `server_identity` row in `server.db` and the local owner's session in one transaction: an immutable UUIDv7 `server_id`, an Ed25519 signing keypair (`SigningKey` 32-byte seed kept in `server.db`, 32-byte `public_key` for pinning), a display `name`, `role` (`Role::Unassigned` initially), and `library_id` (`None`).
- **Proof of identity (`secret.rs`, `/v1/descriptor`):** A client that pins a server's `public_key` asks the descriptor with a fresh nonce, and the server answers with an Ed25519 signature over it (`descriptor_proof`), so the client knows it reached the holder of that key before it sends a credential.
- **Authoritative hub pointer (`library_store.rs`, `apps/server/src/library.rs`):** `server_identity.role` is only the server's own claim. Which server may write `library.db` is decided solely by `library_meta.hub_server_id` inside `library.db` (`hub_epoch` is initialized to `1` and logged at startup, reserved for future hub moves). Before opening `library.db` for writing, a hub checks `LibraryStore::check` (read-only, so a refused database is never migrated or touched) and verifies that `library_meta.library_id` matches `server_identity.library_id` and `hub_server_id` names this server. Every `LibraryStore::write` transaction re-checks `hub_server_id` and fails with `Error::NotTheHub` if ownership changed.
- **Crash-safe library creation (`library.create` in `dispatch.rs`, `apps/ritornelctl/src/library.rs`):** Creating a library writes `library.db` first (setting `hub_server_id` to this server, `hub_epoch = 1`, and recording the command receipt in one transaction) and then updates `server.db` (`role = 'hub'`, `library_id`). If the process stops between the two files, startup sees an `unassigned` server whose `library.db` already names it as hub and finishes claiming it in `server.db`; if `library.db` names a different server, an `unassigned` server leaves it untouched and runs without a library.

## Local credentials, sessions, and tokens

- **Local owner credential (`apps/server/src/credential.rs`):** On first start, the server issues a 32-byte random `SessionToken` (64 hex digits) for the local owner (`SessionKind::Full`, `SubjectKind::Person`), stores only its SHA-256 hash in `server.db`'s `session` table, and writes the token atomically (`create_private_file` + `sync_all` + rename) to an owner-only file in the data directory. On subsequent starts, `credential::ensure` verifies the file via `platform::is_private` and matches it against the stored hash; if missing, readable by other users, or mismatched, the previous local session is revoked and a fresh token is issued.
- **Constant-time verification and audit attribution:** `Verifier` holds only the SHA-256 hash in memory and checks presented `Authorization: Bearer` tokens with `subtle::ConstantTimeEq`. Every library write stamps `library_revision` with the handling session's `public_id` and `SubjectKind` (`person`, `agent`, or `server`).
- **Session capabilities (`SessionKind`):** Sessions are `Full` or `Limited` (see ["Session and frames" in `docs/internals/contract.md`](contract.md#session-and-frames) for the calls restricted to `Full`). Sessions end only by revocation (`revoked_at_ms`), never by age.
- **Single-use socket tickets (`apps/server/src/ticket.rs`, `crates/ritornel-contract/src/ticket.rs`):** Browser or WebView clients that cannot attach `Authorization` headers to WebSocket upgrades exchange their bearer credential at `POST /v1/ticket` for a 64-hex `SocketTicket` stored in memory only (`MAX_WAITING = 64`, 10-second lifetime, constant-time lookup, consumed on first presentation).
- **Session-scoped media tokens (`apps/server/src/media.rs`):** `media.token` issues one 64-hex token per active WebSocket session, held in memory only (`MediaTokens`), valid exclusively for `GET /v1/art/{artId}/{size}?token=`, and revoked automatically when the session closes.

## Listener and transport boundaries

- **Loopback or the private network (`apps/server/src/config.rs`):** `Listen` binds IPv4 loopback (`127.0.0.1`) by default, on `DEFAULT_PORT` (`4747`) with fallback to an OS-chosen port (`0`) when unspecified and already in use. `private:<port>` binds every IPv4 interface and closes any connection whose peer is not loopback, private, link-local or in the tailnet range before reading a byte (`Listen::admits`). No other address can be named, so a public address is never bound. Clients discover the active port from `server.json` rather than assuming `4747`.
- **Authenticated routes and bounds (`apps/server/src/listener.rs`, `dispatch.rs`):** Every HTTP route except `GET /v1/descriptor` requires authentication (bearer header, one-time ticket on `GET /v1/ws`, or media token on `GET /v1/art/…`), even on loopback, to block cross-origin browser requests to `127.0.0.1` (see ["Query-string credentials and origin checks" in `docs/internals/contract.md`](contract.md#query-string-credentials-and-origin-checks)). Connection admission is bounded by `Bounds::max_connections` and `Bounds::header_wait` before auth, HTTP request heads are capped at `MAX_HEAD_BYTES` (`16 KiB`), and WebSocket control frames are capped at `MAX_MESSAGE_BYTES` (`1 MiB`) so bulk transfers stay off the control channel.

## Hub and satellites

A hub owns `library.db`. A satellite is another server that plays and records through the hub's library rather than holding one of its own. The server side lives in `apps/server/src/link.rs` and `apps/server/src/dispatch/link.rs`, storage in `crates/ritornel-engine/src/link_store.rs`, wire types in `crates/ritornel-contract/src/link.rs`, and the command line in `apps/ritornelctl/src/link.rs`. ["Link sessions" in `docs/internals/contract.md`](contract.md#link-sessions) has the invite, the request and what the hub refuses.

- **Invite and join:** `link.invite` on the hub makes a one-time invite naming the hub's ID, its public key, and the routes it is reached on. `link.join` on the other server dials those routes, best first as below, checks the descriptor proof against the key in the invite, and proves its own key over the invite's secret. The secret travels after `#`, so it is never part of a route or a log line.
- **Routes:** A route is a host and a port. The host is an address on a private network or a tailnet, or a name (`link::check_routes`), and an invite names at most eight. Unless `--route` names others, an invite offers these, found as it is made (`found_routes`):
  - this machine's multicast DNS (Bonjour) name, such as `studio-mac.local` (`platform::mdns_name`);
  - the address it sends from on the default route;
  - its addresses in the tailnet range `100.64.0.0/10`, read from its network interfaces, which finds Tailscale's and NetBird's alike.

  A satellite keeps the routes as the invite named them, and at every dial resolves them all again with the system resolver (`link::resolve`), so a hub found by its name is found after its address changes. It then orders what they give by where it leads (`link::candidates`): an address on this network written as an address, then a name that resolves to one, such as the `.local` name, then a tailnet; among equals, the invite's order holds, and an address two routes give is tried once. What a route resolved to, or that it resolved to nothing, is used again for 30 seconds, so a name that does not resolve, such as a `.local` name away from home, holds up only the first connection in that time. It asks the best first, and the next as well when that one fails or has not answered within half a second (`link::first_answer`), taking the first that answers. So a satellite that connects at home pulls masters over its own network, and uses a tunnel only when that does not answer. A connection already open keeps its way until it drops: one made over a tunnel away from home stays on it after coming home, until the next dial. A name may resolve to several addresses. Each IPv4 address on a private network or a tailnet is tried in turn, up to four a route; the hub listens on IPv4, and a public address is never dialled. A name gets three seconds to resolve and an address four to answer, so one that never does leaves the next its chance.
- **A name is not trusted:** A name that resolves to another machine, by mistake or by spoofing, gets nothing but a nonce. Before anything else is sent, the satellite asks whatever answers to prove it holds the hub's key (`link::reach`), and a server that cannot is refused like any other. The proof does not stop what plain HTTP cannot: someone able to relay traffic on the network reads what travels, by a name as by an address. That is why a route must be private, or inside a tailnet's encryption.
- **Resolving `.local`:** macOS and Windows resolve `.local` names themselves. A Windows hub offers its DNS host name, the name it answers to by mDNS. A hub on Linux offers its name only while Avahi runs, and a satellite on Linux resolves one only with nss-mdns (Avahi's `mdns4_minimal` in `/etc/nsswitch.conf`) or with mDNS turned on in `systemd-resolved`. Without it, the satellite falls back to the routes that follow the name.
- **A tailnet's own name:** A name a tailnet gives the machine, such as NetBird's `<host>.netbird.cloud` or Tailscale's MagicDNS name, is not found on its own. Pass it when making the invite: `ritornelctl link invite --route studio.example-overlay.net:4747`. Routes given this way replace the ones the hub finds, so name each wanted with its own `--route`.
- **What each side keeps:** The hub registers the satellite in `library.db`'s `server` table and issues it a link session in `server.db` (`SubjectKind::Server`, with the satellite's ID and the public key it proved). The satellite keeps one `hub_link` row in `server.db`: the hub's ID and pinned key, its name, the routes, and the link session's token. It takes `Role::Satellite` and the hub's library ID.
- **Forwarding:** A satellite answers its own status, player, queue, output, link and backups, and forwards library calls to its hub on a connection of the client session's own (`apps/server/src/uplink.rs`, `on_a_satellite`). The player, the queue and the outbox are the satellite's own. ["Satellites" in `docs/internals/contract.md`](contract.md#satellites) has the routes, deadlines and the `hub_unreachable` error.
- **Playing the hub's music:** A satellite's player reads the hub's library through `HubCatalog` (`apps/server/src/hub_catalog.rs`): a track and its copies with `link.tracks` and `link.copies`, and a master pulled whole with the link session from `GET /v1/audio/…` into the satellite's `cache/audio` before it plays. The cache holds at most `DEFAULT_CACHE_BYTES` (2 GiB) or what the `cache_size` setting says, and the oldest masters go first, never the one just pulled. What is already playing, and any master already pulled, plays on while the hub is away.
- **Listens:** A satellite records its listens in its own `server.db` and its outbox delivers each to the hub with `link.listen`, keyed on the satellite's player endpoint and the listen's ID, so a resend is a duplicate and nothing is counted twice. Listens made while the hub is away wait in the outbox. The hub alone writes the history and scrobbles.
- **One contract:** A hub refuses a satellite that speaks another `CONTRACT_VERSION`, and the refusal says which side is older and so which to update (`link::versions_differ`).
- **Which machine is which:** Each server is named after its computer, so a hub lists its satellites, and a satellite names its hub, by the machines' own names (["Server name" in `docs/internals/server.md`](server.md#server-name)).
- **A hub stays awake while it is used:** By default the hub keeps its machine from idle sleep while a linked server plays, or has made a call within the last 30 minutes, and lets it sleep otherwise. Being linked alone keeps nothing awake, since a player stays linked for good. Another window, always, or never can be chosen with `ritornelctl link awake`, kept with the server (["Keeping a hub awake" in `docs/internals/server.md`](server.md#keeping-a-hub-awake)).
- **A satellite's clients hear of its hub:** A satellite sends its clients a `servers` event each time the hub begins or stops answering, and pings the hub every ten seconds (`link.ping`, which also says whether it plays) so that a hub that went while nothing was asked is found out (`uplink::follow`). The desktop app waits a few seconds before saying the hub is away, marks it in the title bar, and says when it is back.
- **Status:** `link.status` reports the link from either side: on a hub its satellites, on a satellite its hub. On a satellite it also says how the hub was last reached (`HubStatus::route`): the route as the link names it, and the address it resolved to where that differs, such as `studio-mac.local:4747 (192.168.1.20:4747)`. It also says whether the hub answers. `ritornelctl link status` shows them as "Connected via" (or "Last reached via" once the hub does not answer) and "Hub answers".

## Decisions

- **Authoritative hub pointer in `library.db`.** Storing `hub_server_id` inside the library itself prevents accidental split-brain writes when a database file is copied or moved between machines.
- **Hash-only token storage and owner-only credential file.** Keeping only SHA-256 hashes in `server.db` and validating file permissions on every startup means a compromised or misconfigured file fails closed and rotates automatically.
- **Authenticated loopback and short-lived tickets.** Requiring credentials even on `127.0.0.1` protects local servers from hostile browser pages while keeping tickets and media tokens memory-only and narrowly scoped.
- **Plain HTTP only where it stays private.** A link travels as plain HTTP, so a route is dialled only at a private or tailnet address. On a tailnet such as NetBird or Tailscale, the WireGuard overlay encrypts what travels, which is what makes plain HTTP acceptable there, even away from home.
- **1 MiB control-frame ceiling.** Bounding JSON-RPC WebSocket frames keeps control traffic responsive and forces artwork and bulk transfers onto HTTP routes.
